======================================================================
 COMMUNITY STORE (ANDROID) - FIREBASE SETUP GUIDE
======================================================================

This guide connects the app to YOUR OWN Firebase project so you can
build, run and test it. Follow the parts in order. Everything is done
in a web browser (Firebase console) and in Windows PowerShell.

Time needed: about 20-30 minutes.

----------------------------------------------------------------------
 WHAT YOU NEED
----------------------------------------------------------------------
 - A Windows PC with Android Studio installed (keep it UPDATED - see
   Troubleshooting if it says "incompatible version of the Android
   Gradle plugin").
 - A Google account (for Firebase).
 - An Android phone with a USB cable, OR an Android emulator.
 - Node.js (only for the PowerShell / Firebase CLI part).
   Download the "LTS" version from https://nodejs.org and install it
   with the default options.

Words used in this guide:
 - "Firebase console" = https://console.firebase.google.com
 - "Project ID"      = the short id of your Firebase project, for
                       example: my-community-store-1a2b3
                       (Firebase console -> gear icon -> Project settings
                       -> General -> "Project ID")
 - "Project root"    = the folder that contains this file, gradlew.bat
                       and the "app" folder.


======================================================================
 PART 1 - CREATE A FIREBASE PROJECT
======================================================================
 1. Open https://console.firebase.google.com and sign in.
 2. Click "Create a project" (or "Add project").
 3. Type any name, e.g. Community Store Test. Click Continue.
 4. Google Analytics: you can turn it OFF. Click "Create project".
 5. Wait until it says the project is ready, then click Continue.
 6. Write down your Project ID (gear icon -> Project settings ->
    General -> Project ID). You need it in Part 3.


======================================================================
 PART 2 - ADD THE ANDROID APP AND DOWNLOAD google-services.json
======================================================================
 1. In your project, open: gear icon -> Project settings -> General.
 2. Scroll to "Your apps" and click the Android icon ("Add app").
 3. Android package name - type EXACTLY:

        com.example.communitystore

 4. App nickname: anything. Debug signing certificate: leave empty.
 5. Click "Register app".
 6. Click "Download google-services.json".
 7. Put the downloaded file in the "app" folder of the project:

        <project root>\app\google-services.json

    (Next to app\build.gradle.kts. If a google-services.json is
    already there, replace it.)
    The file name must be exactly google-services.json - Windows
    sometimes saves it as "google-services (1).json". Rename it if so.
 8. Click Next / Continue until the wizard finishes. You do NOT need
    to change any Gradle files - the project is already set up.


======================================================================
 PART 3 - SET YOUR PROJECT'S LINK DOMAIN (ONE LINE)
======================================================================
Email-verification and password-reset links use your project's
domain. It is set in ONE place.

 1. Open this file in Android Studio or Notepad:

        <project root>\app\build.gradle.kts

 2. Near the top, find this line:

        val firebaseAuthHost = "community-store-de45f.firebaseapp.com"

 3. Replace the text between the quotes with your Project ID followed
    by .firebaseapp.com, for example:

        val firebaseAuthHost = "my-community-store-1a2b3.firebaseapp.com"

 4. Save the file.


======================================================================
 PART 4 - TURN ON EMAIL/PASSWORD SIGN-IN
======================================================================
 1. Firebase console -> your project.
 2. Left menu: Build -> Authentication
    (newer consoles: Security -> Authentication, or use the search bar).
 3. Click "Get started" if you see it.
 4. Open the "Sign-in method" tab.
 5. Click "Add new provider" -> "Email/Password".
 6. Turn ON the first switch "Email/Password".
    Leave "Email link (passwordless sign-in)" OFF.
 7. Click Save. The list must now show:  Email/Password   Enabled


======================================================================
 PART 5 - CREATE THE FIRESTORE DATABASE
======================================================================
 1. Left menu: Build -> Firestore Database
    (newer consoles: Databases and storage -> Firestore).
 2. Click "Create database".
 3. Database ID: leave "(default)".
 4. Location: pick one close to you, e.g. africa-south1 (Johannesburg).
    This cannot be changed later.
 5. Choose "Start in test mode" and click Create.

 IMPORTANT: test mode lets anyone read/write and STOPS WORKING after
 30 days. Before that (or right away), replace the rules:

 6. In Firestore, open the "Rules" tab.
 7. Delete everything in the editor and paste this:

----------------------------- copy from here -------------------------
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Account documents: each user can only read/write their own.
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
    match /vendors/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
    match /residences/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }

    // Marketplace products: any signed-in user can read,
    // only the seller can create/change their own products.
    match /products/{productId} {
      allow read: if request.auth != null;
      allow create: if request.auth != null
                    && request.resource.data.sellerId == request.auth.uid;
      allow update, delete: if request.auth != null
                    && resource.data.sellerId == request.auth.uid;
    }
  }
}
------------------------------ copy to here --------------------------

 8. Click "Publish".

 (These rules are for development/testing. Review them before the app
 is used by real people.)


======================================================================
 PART 6 - STORAGE (FOR FILE AND PHOTO UPLOADS)
======================================================================
Storage is used for:
 - the Residence registration PDF (appointment letter),
 - the Vendor registration document,
 - product photos in "Add Product".

NOTE: New Firebase projects only get Storage on the "Blaze"
(pay-as-you-go) plan. Blaze has a free monthly allowance, so testing
normally costs nothing, but Google asks for a billing card.

 OPTION A - Use Storage (everything works):
  1. Left menu: Build -> Storage (or Databases and storage -> Storage).
  2. If asked, click "Upgrade project" and set up the Blaze plan.
  3. Click "Get started" -> choose the SAME location as Firestore
     -> "Start in test mode" -> Create.
  4. Open the "Rules" tab, delete everything and paste:

----------------------------- copy from here -------------------------
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /residence_documents/{uid}/{allPaths=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
    match /vendor_documents/{uid}/{allPaths=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
    match /product_images/{uid}/{allPaths=**} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
------------------------------ copy to here --------------------------

  5. Click "Publish".

 OPTION B - Skip Storage (no card needed):
  - Do NOT register Residence/Vendor accounts inside the app (the PDF
    upload fails with "Upload failed: Object does not exist at
    location"). Create the test account in the console instead
    (Part 7, Method 1).
  - In "Add Product", publish WITHOUT adding photos.


======================================================================
 PART 7 - CREATE AND APPROVE A RESIDENCE TEST ACCOUNT
======================================================================
Residence accounts must be approved manually before they can log in.
"Approved" means: a document in the Firestore "users" collection whose
Document ID is the user's UID, with role = residence and
verified = true.

 STEP 7.1 - Create the user (choose ONE method)

  Method 1 (works without Storage):
   1. Firebase console -> Authentication -> "Users" tab -> "Add user".
   2. Type a test email (e.g. residence.test@example.com) and a
      password (at least 6 characters). Click "Add user".

  Method 2 (needs Storage, Part 6 Option A):
   1. In the app: Register -> choose "Residence" -> fill in the form
      -> upload a PDF -> "Submit for Approval".

 STEP 7.2 - Copy the user's UID
   1. Firebase console -> Authentication -> "Users" tab.
   2. Find the email and copy the value in the "User UID" column
      (hover over it and click the copy icon).

 STEP 7.3 - Approve the user
   1. Firebase console -> Firestore Database -> "Data" tab.
   2. If there is no "users" collection yet: click "+ Start collection",
      Collection ID: users, click Next.
      If "users" already exists: click it, then "+ Add document".
   3. Document ID: PASTE THE UID (do NOT click "Auto-ID").
   4. Add these fields (click "+ Add field" for each one).
      The TYPE matters - "verified" must be boolean, not string:

        Field name     Type       Value
        -----------    -------    --------------------------
        role           string     residence
        verified       boolean    true
        displayName    string     Test Resident  (any name)
        email          string     the user's email

   5. Click Save.
   6. (Only if you used Method 2) also open the "residences"
      collection -> the document with the same UID -> change
      verificationStatus to: approved

 Now log in on the phone with that email and password. You should land
 on the purple Residence Dashboard ("Good morning , Test").

 (Other roles: the same users document with role = student, faculty or
 vendor. Student and faculty accounts must also verify their email.)


======================================================================
 PART 8 - POWERSHELL: FIREBASE CLI (OPTIONAL BUT USEFUL)
======================================================================
The Firebase CLI lets you check your login and projects, and look up
user UIDs from PowerShell.

 Open PowerShell: press the Windows key, type "PowerShell", press
 Enter. Type each command below and press Enter.

 8.1 Install the Firebase CLI (needs Node.js, see "What you need"):

        npm install -g firebase-tools

     Check it worked (prints a version number like 15.x.x):

        firebase --version

     If you see "running scripts is disabled on this system", run this
     once, answer Y, then try again:

        Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

 8.2 Log in (a browser window opens - choose the Google account that
     owns your Firebase project, then click Allow):

        firebase login

     You should see:  Success! Logged in as <your email>

     Check which account is logged in at any time:

        firebase login:list

 8.3 Check you can see your project (your Project ID must be listed):

        firebase projects:list

 8.4 Make your project the default for this folder. First go to the
     project root (change the path to where YOUR copy is):

        cd "C:\path\to\community-store-android-main"

     Then:

        firebase use --add

     Pick your project with the arrow keys, press Enter, and type the
     alias:  default
     (This updates the .firebaserc file in the project root.)

 8.5 Find user UIDs from PowerShell (alternative to Part 7, Step 7.2):

        firebase auth:export users.json --format=json
        Get-Content users.json | ConvertFrom-Json |
            Select-Object -ExpandProperty users |
            Format-Table localId, email
        Remove-Item users.json

     "localId" is the UID. The last command deletes the export file -
     do not share or keep it, it contains password hashes.

 8.6 Log out of the Firebase CLI when you are done (optional):

        firebase logout


======================================================================
 PART 9 - BUILD AND RUN THE APP
======================================================================
 OPTION A - Android Studio (easiest):
  1. File -> Open -> select the project root. Wait for "Gradle sync"
     to finish (progress bar at the bottom).
  2. Phone: Settings -> About phone -> Software information -> tap
     "Build number" 7 times. Then Settings -> Developer options ->
     turn on "USB debugging". Plug the phone in and tap "Allow".
     OR create an emulator: Device Manager -> + -> Create Virtual
     Device -> pick a Pixel -> pick a system image -> Finish.
  3. Select "app" and your device in the top toolbar, click the green
     Run button.

 OPTION B - PowerShell (use this if Android Studio shows the
 "incompatible version of the Android Gradle plugin" error):
  1. Plug in the phone (USB debugging on, see Option A step 2).
  2. In PowerShell, go to the project root:

        cd "C:\path\to\community-store-android-main"

  3. Use Android Studio's built-in Java for this window:

        $env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"

  4. Build the app:

        .\gradlew.bat assembleDebug

     Wait for "BUILD SUCCESSFUL" (the first build can take several
     minutes).
  5. Check the phone is connected (it must be listed as "device"):

        & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices

  6. Install the app on the phone:

        & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk

     Wait for "Success", then open "CommunityStore" on the phone.

 After switching to a DIFFERENT Firebase project, uninstall the old
 app from the phone first (it may remember a login from the other
 project):

        & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" uninstall com.example.communitystore


======================================================================
 PART 10 - OPTIONAL: OPEN EMAIL LINKS DIRECTLY IN THE APP
======================================================================
Only needed for Student/Faculty email verification and the password
reset screen to open INSIDE the app. Residence/Vendor testing does not
need this. Requires Part 8 (Firebase CLI) to be done.

 1. Get your computer's debug SHA-256 fingerprint. Build the app once
    first (Part 9) so the debug key exists, then in PowerShell run
    this as ONE line:

        & "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -list -v -keystore "$env:USERPROFILE\.android\debug.keystore" -alias androiddebugkey -storepass android -keypass android

    Copy the value after "SHA256:" (it looks like 49:C8:B5:0A:...).
    Every computer has its own debug key, so each person must do this
    on their own PC.
 2. Firebase console -> Project settings -> General -> Your apps ->
    your Android app -> "Add fingerprint" -> paste it -> Save.
 3. Open  public\.well-known\assetlinks.json  in Notepad and replace
    the value inside "sha256_cert_fingerprints" with your SHA-256.
    Save.
 4. Deploy the website part (needs Firebase Hosting, free):

        firebase deploy --only hosting

 5. Rebuild and reinstall the app (Part 9).


======================================================================
 TROUBLESHOOTING
======================================================================
 "File google-services.json is missing" (build error)
   -> Part 2, step 7. Check the file is in the "app" folder and the
      name is exactly google-services.json.

 "No matching client found for package name" (build error)
   -> The Android app in Firebase was registered with a different
      package name. Add a new Android app with exactly
      com.example.communitystore (Part 2) and download the new file.

 "The project is using an incompatible version of the Android Gradle
  plugin" (Android Studio)
   -> Update Android Studio: Help -> Check for Updates. Or build with
      PowerShell (Part 9, Option B).

 "Account not found. Please complete registration first." (login)
   -> There is no "users" document for this account. Do Part 7,
      Step 7.3. Check the Document ID is the UID, not an Auto-ID.

 "Your account is not active." (login)
   -> In the users document: "verified" must be type boolean with
      value true, and "role" must be exactly residence, vendor,
      student or faculty (lowercase, no spaces).

 "Your residence administrator application is still under review."
   -> The account registered in the app but was not approved yet. Do
      Part 7, Step 7.3.

 "Upload failed: Object does not exist at location"
   -> Storage is not set up. Part 6, Option A (or use Option B).

 "PERMISSION_DENIED" / "Missing or insufficient permissions"
   -> Firestore or Storage rules. Check Part 5 (steps 6-8) and Part 6.
      If you used test mode, it may have expired after 30 days.

 "Please verify your email first." (Student/Faculty only)
   -> Open the verification email and click the link. Check spam.

 The app opens but shows old data / wrong account
   -> Uninstall the app and install again (end of Part 9).


======================================================================
 SWITCHING BACK TO THE TEAM'S FIREBASE PROJECT
======================================================================
 1. Put the team's google-services.json in the "app" folder.
 2. In app\build.gradle.kts set:
        val firebaseAuthHost = "community-store-de45f.firebaseapp.com"
 3. Uninstall the app from the phone, then rebuild and install
    (Part 9).
